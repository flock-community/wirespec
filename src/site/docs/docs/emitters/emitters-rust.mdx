# Rust Emitter

The Rust emitter generates structs, enums, modules and traits. Besides the standard library, it uses the
[`regex`](https://crates.io/crates/regex) crate to validate refined types. The traits declare `async fn`, which needs
Rust 1.75 or newer. This page shows the code it generates for the [Todo example](./emitters.mdx#the-example):

```shell
wirespec compile -i todo.ws -o out -l Rust -p community.flock.todo --shared
```

```text
out
└── community/flock/todo
    ├── mod.rs
    ├── wirespec.rs
    ├── client.rs
    ├── channel/todo_events.rs
    ├── client/update_todo_client.rs
    ├── endpoint/update_todo.rs, mod.rs
    ├── generator/todo_generator.rs, todo_id_generator.rs, ...
    ├── model/todo.rs, todo_id.rs, priority.rs, todo_event.rs, ..., mod.rs
    └── rpc/complete_todo.rs
```

File and field names are converted to snake case, so `dueDate` becomes `due_date` and `requestId` becomes
`request_id`. Every file starts with the `use` declarations it needs, which are left out of the examples below.

## Type

A type becomes a `struct` with a `validate` method:

```rust title="model/todo.rs"
#[derive(Debug, Clone, Default, PartialEq)]
pub struct Todo {
    pub id: TodoId,
    pub title: String,
    pub done: bool,
    pub priority: Priority,
    pub tags: Vec<String>,
    pub due_date: Option<String>,
}
impl Todo {
    pub fn validate(&self) -> Vec<String> {
        return if !self.id.validate() { vec![String::from("id")] } else { Vec::<String>::new() };
    }
}
```

The fields map to Rust types as follows:

| Wirespec    | Rust                                    |
|-------------|-----------------------------------------|
| `String`    | `String`                                |
| `Integer`   | `i64`                                   |
| `Integer32` | `i32`                                   |
| `Number`    | `f64`                                   |
| `Number32`  | `f32`                                   |
| `Boolean`   | `bool`                                  |
| `Bytes`     | `Vec<u8>`                               |
| `T[]`       | `Vec<T>`                                |
| `{ T }`     | `std::collections::HashMap<String, T>`  |
| `T?`        | `Option<T>`                             |

`validate` returns the names of the fields that do not hold a valid value. Only refined values can be invalid, so
`Todo` checks `id`. A type that contains another type passes on its errors with the field name as a prefix:

```rust title="model/todo_created.rs"
#[derive(Debug, Clone, Default, PartialEq)]
pub struct TodoCreated {
    pub todo: Todo,
}
impl TodoCreated {
    pub fn validate(&self) -> Vec<String> {
        return self.todo.validate().iter().map(|e| format!("todo.{}", e)).collect::<Vec<_>>();
    }
}
```

## Refined

A refined type becomes a `struct` that wraps the value. `validate` checks the regular expression, and `to_string`
returns the plain value:

```rust title="model/todo_id.rs"
#[derive(Debug, Clone, Default, PartialEq)]
pub struct TodoId {
    pub value: String,
}
impl TodoId {
    pub fn validate(&self) -> bool {
        return regex::Regex::new(r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$").unwrap().is_match(&self.value);
    }
    pub fn to_string(&self) -> String {
        return self.value.clone();
    }
}
```

A refined `Integer` or `Number` checks its bounds instead.

## Enum

An enum becomes an `enum` that implements the `Enum` trait, which converts between a variant and its label, the value
as it is written in Wirespec. `Display` prints the label:

```rust title="model/priority.rs"
#[derive(Debug, Clone, PartialEq)]
pub enum Priority {
    LOW,
    MEDIUM,
    HIGH,
}
impl Enum for Priority {
    fn label(&self) -> &str {
        match self {
            Priority::LOW => "LOW",
            Priority::MEDIUM => "MEDIUM",
            Priority::HIGH => "HIGH",
        }
    }
    fn from_label(s: &str) -> Option<Self> {
        match s {
            "LOW" => Some(Priority::LOW),
            "MEDIUM" => Some(Priority::MEDIUM),
            "HIGH" => Some(Priority::HIGH),
            _ => None,
        }
    }
}
impl std::fmt::Display for Priority {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        write!(f, "{}", self.label())
    }
}
```

## Union

A union becomes an `enum` with a variant for every member, so a `match` over a `TodoEvent` is exhaustive:

```rust title="model/todo_event.rs"
#[derive(Debug, Clone, PartialEq)]
pub enum TodoEvent {
    TodoCreated(TodoCreated),
    TodoDeleted(TodoDeleted),
}
```

## Endpoint

An endpoint becomes a module, `endpoint/update_todo.rs`, that holds everything that is needed to send and receive the
request and its responses.

### Request

The path parameters, query parameters and request headers each get a struct. `Request` combines them with the method
and the body, and `Request::new` takes all values as flat parameters:

```rust title="endpoint/update_todo.rs"
#[derive(Debug, Clone, Default, PartialEq)]
pub struct Path {
    pub id: TodoId,
}
#[derive(Debug, Clone, Default, PartialEq)]
pub struct Queries {
    pub notify: Option<bool>,
}
#[derive(Debug, Clone, Default, PartialEq)]
pub struct RequestHeaders {
    pub request_id: String,
}
#[derive(Debug, Clone, Default, PartialEq)]
pub struct Request {
    pub path: Path,
    pub method: Method,
    pub queries: Queries,
    pub headers: RequestHeaders,
    pub body: TodoInput,
}
impl Request {
    pub fn new(id: TodoId, notify: Option<bool>, request_id: String, body: TodoInput) -> Self {
        Request {
            path: Path { id: id },
            method: Method::PUT,
            queries: Queries { notify: notify },
            headers: RequestHeaders { request_id: request_id },
            body: body
        }
    }
}
```

### Responses

Every status code gets a response struct, with a struct for its headers. The enum `Response` has a variant for every
response, and `Response2XX`, `Response4XX`, `ResponseTodo` and `ResponseApiError` group them per status class and per
body type:

```rust title="endpoint/update_todo.rs"
#[derive(Debug, Clone, PartialEq)]

    pub version: i64,

    pub status: i32,
```

### Serialization

The inner module `UpdateTodo` has four functions that convert between the typed request and response and the
`RawRequest` and `RawResponse` that go over the wire. They delegate the serialization of the path, parameters, headers
and body to a `Serializer` or `Deserializer`:

```rust title="endpoint/update_todo.rs"
pub mod UpdateTodo {
    use super::*;
    pub fn to_raw_request(serialization: &impl Serializer, request: Request) -> RawRequest {
        return RawRequest { method: format!("{:?}", request.method), path: vec![String::from("todos"), serialization.serialize_path(&request.path.id, std::any::TypeId::of::<TodoId>())], queries: std::collections::HashMap::from([(String::from("notify"), request.queries.notify.as_ref().map(|it| serialization.serialize_param(it, std::any::TypeId::of::<bool>())).unwrap_or(Vec::<String>::new()))]), headers: std::collections::HashMap::from([(String::from("requestId"), serialization.serialize_param(&request.headers.request_id, std::any::TypeId::of::<String>()))]), body: Some(serialization.serialize_body(&request.body, std::any::TypeId::of::<TodoInput>())) };
    }
    // ...
}
```

`from_raw_request`, `to_raw_response` and `from_raw_response` work the same way.

### Handler and Call

`Handler` is the trait the server implements, `Call` is the trait the client implements. Every type that implements the
shared `Client` trait, by providing a `Transportation` and a `Serialization`, gets a `Handler` that sends the request.
`Api` describes the endpoint for frameworks with its path template and method:

```rust title="endpoint/update_todo.rs"
    pub trait Handler {
        async fn update_todo(&self, request: Request) -> Response;
    }
    pub trait Call {
        async fn update_todo(&self, id: TodoId, notify: Option<bool>, request_id: String, body: TodoInput) -> Response;
    }
    impl<C: Client> Handler for C {
        async fn update_todo(&self, request: Request) -> Response {
            let raw = to_raw_request(self.serialization(), request);
            let resp = self.transport().transport(&raw).await;
            from_raw_response(self.serialization(), resp)
        }
    }
    pub struct Api;
    impl Server for Api {
        type Req = Request;
        type Res = Response;
        fn path_template(&self) -> &'static str { "/todos/{id}" }
        fn method(&self) -> Method { Method::PUT }
    }
```

## Channel

A channel becomes a module with a `Sender` trait to publish messages and a `Listener` trait to receive them:

```rust title="channel/todo_events.rs"
pub mod TodoEvents {
    use super::*;

        fn todo_events(message: TodoEvent);
    }

        fn todo_events(handler: Box<dyn Fn(TodoEvent) -> ()>);
    }

```

## RPC

An RPC becomes a module with a `Service` trait to implement. Because `CompleteTodo` declares an error, the service
returns a `Response` enum with a `Result` and an `Error` variant. Without an error, it returns the result type
directly:

```rust title="rpc/complete_todo.rs"
pub mod CompleteTodo {
    use super::*;
    #[derive(Debug, Clone, PartialEq)]
    pub enum Response {
        Result(Result),
        Error(Error),
    }
    #[derive(Debug, Clone, Default, PartialEq)]
    pub struct Result {
        pub value: Todo,
    }
    #[derive(Debug, Clone, Default, PartialEq)]
    pub struct Error {
        pub value: ApiError,
    }
    pub trait Service {
        async fn complete_todo(id: TodoId) -> Response;
    }
}
```

## Client

For every endpoint, a client implements its `Call` trait. It builds the `Request`, converts it with `to_raw_request`,
sends it with a `Transportation` and converts the answer with `from_raw_response`:

```rust title="client/update_todo_client.rs"
pub struct UpdateTodoClient<'a, S: Serialization, T: Transportation> {
    pub serialization: &'a S,
    pub transportation: &'a T,
}
impl<'a, S: Serialization, T: Transportation> update_todo::UpdateTodo::Call for UpdateTodoClient<'a, S, T> {
    async fn update_todo(&self, id: TodoId, notify: Option<bool>, request_id: String, body: TodoInput) -> update_todo::Response {
        let request = update_todo::Request::new(id, notify, request_id, body);
        let raw_request = update_todo::UpdateTodo::to_raw_request(self.serialization, request);
        let raw_response = self.transportation.transport(&raw_request).await;
        update_todo::UpdateTodo::from_raw_response(self.serialization, raw_response)
    }
}
```

`Client` in `client.rs` implements the `Call` trait of every endpoint in the specification, so one instance can call
the whole API:

```rust title="client.rs"
pub struct Client<S: Serialization, T: Transportation> {
    pub serialization: S,
    pub transportation: T,
}
impl<S: Serialization, T: Transportation> update_todo::UpdateTodo::Call for Client<S, T> {
    async fn update_todo(&self, id: TodoId, notify: Option<bool>, request_id: String, body: TodoInput) -> update_todo::Response {
        UpdateTodoClient { serialization: &self.serialization, transportation: &self.transportation }
            .update_todo(id, notify, request_id, body).await
    }
}
```

## Generator

For every type, refined type, enum and union, the emitter also writes a generator to `generator/` that builds an
instance with values from a `Generator`, as described for [Kotlin](./emitters-kotlin.mdx#generator).

## Shared

`wirespec.rs` is the same for every specification. It contains:

| Declarations                                                                 | Purpose                                                       |
|------------------------------------------------------------------------------|---------------------------------------------------------------|
| `Model`, `Shape`, `Enum`, `Refined`                                          | The kinds of model; generated enums implement `Enum`          |
| `Endpoint`, `Channel`, `Rpc`, `Handler`, `Call`                              | Marker traits for endpoints, channels and RPCs                |
| `Method`, `Request`, `Response`, `Path`, `Queries`, `Headers`                | The typed request and response of an endpoint                 |
| `Serializer`, `Deserializer`, `Serialization` and their parts                | Plug in the serialization of bodies, paths and parameters     |
| `RawRequest`, `RawResponse`, `Transportation`                                | The untyped request and response, and how to send them        |
| `Generator`, `GeneratorField` and its structs                                | Generate values for the generators                            |
| `Client`, `Server`                                                           | Provide the transport and serialization, and describe an endpoint |

## Default values

The Rust emitter does not support [default values](../language/types.mdx#default-values) yet. Compiling the
[defaults from the example](./emitters.mdx#default-values) to Rust fails, and the error names the fields that have one:

```
Rust does not support default values, but these fields have one: Todo.done, Todo.priority, Todo.dueDate. Remove the
defaults, or leave them out of the generated code with the ignore defaults option: --ignore-defaults for the CLI, or
ignoreDefaults in the Gradle and Maven plugins.
```

To generate Rust anyway, leave the defaults out with the [ignore defaults option](../language/types.mdx#ignoring-defaults):

```shell
wirespec compile -i todo.ws -o out -l Rust -p community.flock.todo --ignore-defaults
```

A [conversion](../converters/converters.md) from OpenAPI or Avro to Rust does not fail: it leaves the defaults out.
