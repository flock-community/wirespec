## Default values

Field [default values](../language/types.mdx#default-values) are generated as constructor parameter defaults:

```wirespec
type Settings {
  name: String = "anonymous",
  retries: Integer = 3,
  port: Integer32 = 8080,
  ratio: Number = 1.5,
  weight: Number32 = 0.5,
  active: Boolean = true,
  nickname: String? = null,
  status: Status = INACTIVE,
  tags: String[]
}

enum Status {
  ACTIVE, INACTIVE
}
```

```kotlin
data class Settings(
  val name: String = "anonymous",
  val retries: Long = 3L,
  val port: Int = 8080,
  val ratio: Double = 1.5,
  val weight: Float = 0.5f,
  val active: Boolean = true,
  val nickname: String? = null,
  val status: Status = Status.INACTIVE,
  val tags: List<String>
) : Wirespec.Shape {
  override fun validate(): List<String> =
    emptyList<String>()
}
```

An enum default refers to the entry of the generated `enum class`, using the same name as the entry. Entries that are
not valid Kotlin names are renamed the same way in both places, so `priority: Priority = 2` becomes
`val priority: Priority = Priority._2`.

Fields with a default can be left out when the model is constructed, so `Settings(tags = listOf("admin"))` is valid.

The default is also used when the field is missing from a JSON payload, as long as the deserializer knows about Kotlin
default arguments:

- **Jackson** needs the Kotlin module, for example `jacksonObjectMapper()`. Wirespec's Spring integration already uses it.
- **kotlinx.serialization** uses the default for every class annotated with `@Serializable`, which is what the
  kotlinx.serialization extension adds. When it encodes JSON, it leaves out properties that are equal to their default
  unless the `Json` instance is configured with `encodeDefaults = true`.

To generate the models without defaults, use the
[ignore defaults option](../language/types.mdx#ignoring-defaults) of the CLI, Gradle or Maven plugin.
