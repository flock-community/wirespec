# OpenAPI v2 Emitter

The OpenAPI v2 emitter writes the specification as a Swagger 2.0 document. This page shows the document it writes for
the [Todo example](./emitters.mdx#the-example):

```shell
wirespec compile -i todo.ws -o out -l OpenAPIV2
```

The output is a single file, `OpenAPI.json`. Types, refined types and enums become schemas in `definitions`, and
endpoints become `paths`. The comment above a type or an endpoint becomes its `description`. The JSON below is
formatted for readability.

## Type

A type becomes an object schema. Every field that is not nullable is `required`, and a field that refers to another
definition becomes a `$ref`:

```json
"Todo": {
  "description": "A todo item",
  "required": ["id", "title", "done", "priority", "tags"],
  "properties": {
    "id": { "$ref": "#/definitions/TodoId" },
    "title": { "type": "string" },
    "done": { "type": "boolean" },
    "priority": { "$ref": "#/definitions/Priority" },
    "tags": { "type": "array", "items": { "type": "string" } },
    "dueDate": { "type": "string" }
  }
}
```

The fields map to schemas as follows:

| Wirespec    | Schema                                          |
|-------------|-------------------------------------------------|
| `String`    | `type: string`                                  |
| `Integer`   | `type: integer`, `format: int64`                |
| `Integer32` | `type: integer`, `format: int32`                |
| `Number`    | `type: number`, `format: double`                |
| `Number32`  | `type: number`, `format: float`                 |
| `Boolean`   | `type: boolean`                                 |
| `Bytes`     | `type: string`, `format: binary`                |
| `T[]`       | `type: array` with the schema of `T` as `items` |
| `{ T }`     | `type: object`                                  |
| `T?`        | The schema of `T`, left out of `required`       |

## Refined

A refined type becomes a schema of its primitive type. A regular expression becomes its `pattern`:

```json
"TodoId": {
  "type": "string",
  "pattern": "/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/g"
}
```

## Enum

An enum becomes a string schema with its values as `enum`:

```json
"Priority": { "type": "string", "enum": ["LOW", "MEDIUM", "HIGH"] }
```

## Union

Swagger 2.0 has no way to say that a value is one of several schemas, so the emitter leaves unions such as `TodoEvent`
out of the document. Use the [OpenAPI v3 emitter](./emitters-open-api-v3.mdx#union) to describe them as a `oneOf`.

## Endpoint

An endpoint becomes an operation on its path, with the name of the endpoint as `operationId`:

- Path parameters become `parameters` of the path, with `in` set to `path`.
- The request body becomes a parameter of the operation, with `in` set to `body`.
- Query parameters and request headers become parameters of the operation, with `in` set to `query` and `header`. A
  nullable parameter is not `required`.
- Every status code becomes a response with its body as `schema` and its `headers`.

```json
"/todos/{id}": {
  "parameters": [{ "type": "object", "in": "path", "name": "id" }],
  "put": {
    "consumes": ["application/json"],
    "produces": ["application/json"],
    "parameters": [
      {
        "required": true,
        "in": "body",
        "schema": { "$ref": "#/definitions/TodoInput" },
        "name": "RequestBody"
      },
      {
        "required": false,
        "type": "boolean",
        "in": "query",
        "name": "notify"
      },
      {
        "required": true,
        "type": "string",
        "in": "header",
        "name": "requestId"
      }
    ],
    "responses": {
      "200": {
        "schema": { "$ref": "#/definitions/Todo" },
        "description": "UpdateTodo 200 response",
        "headers": { "version": { "type": "integer", "format": "int64" } }
      },
      "404": {
        "schema": { "$ref": "#/definitions/ApiError" },
        "description": "UpdateTodo 404 response",
        "headers": {}
      }
    },
    "description": "Update the title and priority of a todo",
    "operationId": "UpdateTodo"
  }
}
```

## Channel and RPC

OpenAPI describes HTTP APIs, so channels and RPCs have no counterpart. The emitter leaves `TodoEvents` and
`CompleteTodo` out of the document.

## Default values

Field [default values](../language/types.mdx#default-values) are written as the `default` of the property schema. With
the [defaults from the example](./emitters.mdx#default-values), `Todo` becomes:

```json
"Todo": {
  "description": "A todo item",
  "required": ["id", "title", "done", "priority", "tags"],
  "properties": {
    "id": { "$ref": "#/definitions/TodoId" },
    "title": { "type": "string" },
    "done": { "type": "boolean", "default": false },
    "priority": { "$ref": "#/definitions/Priority" },
    "tags": { "type": "array", "items": { "type": "string" } },
    "dueDate": { "type": "string" }
  }
}
```

Two kinds of default are left out:

- A `null` default, like the one of `dueDate`. A nullable field is already left out of `required`.
- An enum default, like the one of `priority`. An enum field is written as a `$ref` to the enum's schema, and OpenAPI
  ignores anything next to a `$ref`.

The [OpenAPI converter](../converters/openapi.md#defaults) reads these defaults back.
