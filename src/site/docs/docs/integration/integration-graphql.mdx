The `graphql` integration ships an [IR extension](../plugins/plugins.md#ir-extensions) that generates a typed GraphQL
client from the [rpcs](../language/rpc.mdx) of a contract. Together with the [GraphQL converter](../converters/graphql.md),
which turns every field of `Query` and `Mutation` into an rpc, it gives you a client for a GraphQL API from its schema.

The client comes in two flavours, and you can mix them:

- **Typed calls** select every field of a result and return the models: `client.queryTodo(id)` returns a `Todo`.
- **Selections** let you pick the fields and return a partial result: `client.queryTodo(id) { title() }` returns a
  `TodoResult` with only `title` filled.

The GraphQL documents are written at build time, so the generated code needs no GraphQL library and only uses the
standard library of the language. It sends requests through the same `Wirespec.Transportation` and
`Wirespec.Serialization` as the endpoint clients.

Every example on this page is compiled and tested with the integration, and the generated code is the output of the
extension for the contract below.

## Setup

The extension is bundled with every Wirespec plugin as `GraphQLClient`. Register it with `extensionClasses`, by name in
Maven and by class in Gradle. Convert the schema to Wirespec first, or write the rpcs yourself.

<Tabs groupId="build">
  <TabItem value="gradle" label="Gradle">
    ```gradle title="build.gradle.kts"
    import community.flock.wirespec.integration.graphql.extension.GraphQLClientExtension
    import community.flock.wirespec.plugin.gradle.CompileWirespecTask
    import community.flock.wirespec.plugin.Language

    tasks.register<CompileWirespecTask>("wirespec-compile") {
        input = layout.projectDirectory.dir("src/main/wirespec")
        output = layout.buildDirectory.dir("generated")
        packageName = "community.flock.todo"
        // Language.Kotlin, Language.Java or Language.Scala
        language = Language.Kotlin
        extensionClasses = listOf(GraphQLClientExtension::class.java)
    }
    ```
  </TabItem>
  <TabItem value="maven" label="Maven">
    ```xml title="pom.xml"
    <plugin>
        <groupId>community.flock.wirespec.plugin.maven</groupId>
        <artifactId>wirespec-maven-plugin</artifactId>
        <version>{{WIRESPEC_VERSION}}</version>
        <executions>
            <execution>
                <id>generate</id>
                <goals>
                    <goal>compile</goal>
                </goals>
                <configuration>
                    <input>${project.basedir}/src/main/wirespec</input>
                    <output>${project.build.directory}/generated-sources</output>
                    <packageName>community.flock.todo</packageName>

                    <extensionClasses>
                        <extensionClass>GraphQLClient</extensionClass>
    ```

## The contract

The examples use this contract. Its rpcs are written the way the [GraphQL converter](../converters/graphql.md) writes the
fields of `Query`, `Mutation` and `Subscription`. Two are written by hand: `CompleteTodo` has an
[error type](../language/rpc.mdx#errors), to show how the client returns GraphQL errors as values, and `CountTodos` has
no GraphQL annotation.

```wirespec wirespec source
```

Only rpcs marked `@GraphQLQuery` or `@GraphQLMutation` get a client. `TodoAdded`, a subscription, and `CountTodos`,
without a GraphQL annotation, are left out, so a contract can mix GraphQL operations with rpcs served another way. An rpc
you write yourself needs `@GraphQLName` when the GraphQL field is not named after the rpc, as with `@GraphQLName("todo")`
on `QueryTodo`.

Next to the `model` and `rpc` files, the extension writes the `graphql` package, with one file per operation, and a
`GraphQLClient` in the root package that bundles them, just like the `Client` of the endpoints:

## Creating a client

`GraphQLClient`, in the root package next to the `Client` of the endpoints, implements the `Service` of every operation
at once. It takes a `Wirespec.Serialization` that reads and
writes JSON, and a `Wirespec.Transportation` that sends the request to the path `/graphql`.

## Calling operations

### Errors

A GraphQL response carries errors next to its data.

- An rpc **without an error type** throws an `IllegalStateException` that lists the `Wirespec.GraphQLError`s, with their
  `message`, `locations`, `path` and `extensions`.
- An rpc **with an error type**, such as `CompleteTodo`, returns the first error, read as that type, as its `Error`, and
  the result as its `Result`:

## Selecting fields

To pick the fields yourself, pass a selection. The fields you select are filled and the others are empty, so the call
returns a **partial result**: `QueryTodoGraphQL.TodoResult` instead of `Todo`, with every field nullable.

## Sending requests

The shared `Wirespec` holds the GraphQL counterparts of the endpoint interfaces, so you can send any operation through
one generic client:

```kotlin
interface GraphQLRequest { val query: String }

interface GraphQLClientEdge<Req : GraphQLRequest, Res> {
    fun to(request: Req): RawRequest
    fun from(response: RawResponse): Res
}

interface GraphQLApi<Req : GraphQLRequest, Res> {
    fun client(serialization: Serialization): GraphQLClientEdge<Req, Res>
}

interface GraphQLClient {
    suspend fun <Req : GraphQLRequest, Res> send(api: GraphQLApi<Req, Res>, request: Req): Res
}

data class GraphQLError(val message: String, val locations: List<GraphQLLocation>?, val path: List<Any>?, val extensions: Map<String, Any>?)
data class GraphQLLocation(val line: Int, val column: Int)
```

Like an endpoint, an operation keeps its requests as plain data and turns them into raw requests and back in its own
`toRawRequest` and `fromRawResponse`, which its `api` wraps as a `Wirespec.GraphQLApi`. The result is the result of the
rpc: the model, or the `Result` and `Error` of an rpc with an error type. A selection has its own request and
`selectedApi`, which read the partial result. `Wirespec.GraphQLError` is the error of a response for an rpc without an
error type of its own.

The generated `GraphQLClient` implements `Wirespec.GraphQLClient`, and so can a client of your own, such as one on the
HTTP client of a framework. Code that sends requests depends on the interfaces only, and leaves serialization and
transportation to the client it is given:

## Generated code

Each operation gets a single file in the `graphql` package, next to `model` and `rpc`, that holds everything the
operation needs. The `GraphQLClient` that bundles them sits in the root package, like the `Client` of the endpoints:

| Generated                                | What it is                                                                 |
|------------------------------------------|----------------------------------------------------------------------------|
| `GraphQLClient` (root package)           | Implements `Wirespec.GraphQLClient` and the `Service` of every operation   |
| `QueryTodoGraphQL`, ...                  | The file of one operation; its builder puts a selection in the query       |
| `QueryTodoGraphQL.GraphQLClient`         | The client of the operation                                                |
| `QueryTodoGraphQL.GraphQLRequest`        | The request of every field, a `Wirespec.GraphQLRequest`                    |
| `QueryTodoGraphQL.GraphQLSelectedRequest`| The request of a selection, a `Wirespec.GraphQLRequest`                    |
| `QueryTodoGraphQL.toRawRequest`, ...     | Write a request and read the result, like the functions of an endpoint     |
| `QueryTodoGraphQL.api`, `selectedApi`    | The `Wirespec.GraphQLApi` of each request, which a `GraphQLClient` sends   |
| `QueryTodoGraphQL.GraphQLVariables`, ... | The variables of the requests and the envelopes of the response            |
| `QueryTodoGraphQL.TodoSelection`, ...    | The fields you can select of a type or union the result reaches            |
| `QueryTodoGraphQL.TodoResult`, ...       | The partial result of a type or union the result reaches                   |

A type that several operations return has a selection and a partial result in each of their files, so an operation's
file stands on its own: `QueryTodoGraphQL.TodoResult` and `TodosGraphQL.TodoResult` are different types.

The shapes follow the language:

| Language | Operation file            | A selection of a field                   | Nested types              |
|----------|---------------------------|------------------------------------------|---------------------------|
| Kotlin   | `object`                  | `UserSelection.() -> Unit`, on `this`    | Data classes              |
| Java     | Record without components | `Function<UserSelection, UserSelection>` | Public static records     |
| Scala    | `object`                  | `UserSelection => UserSelection`         | Case classes              |

The client of an operation asks the builder of the operation for the request, writes it with `toRawRequest`, sends it
and reads the result with `fromRawResponse`, like the client of an endpoint. The full query is written at build time; a selection puts its fields in the query. A selection collects the selected fields as
GraphQL text and returns itself from every field. A partial result has the same fields as the model, all nullable:

## The query

- Every parameter of the rpc is a variable, typed and defaulted as the argument of the field it is passed to.
- The field is aliased as `result`, so the client reads it under the same name whatever the field is called.
- A typed call selects every field of the result, all the way down. A union or interface selects `__typename` and an
  inline fragment for each member, so the serialization can tell the members apart by `__typename`.
- GraphQL selects a finite set of fields, so a typed call cannot select a field that refers back to a type it is
  selected in, such as `User.todos` inside `Todo.owner`, or a field that takes a required argument. Such a field is
  left out when it is nullable. When it is not, the build fails with a message that names the field; use a selection
  for that operation instead.

## Configuration

The request goes to the path `/graphql` of the transportation. To call a GraphQL API at another path, rewrite the path in
the transportation:

```kotlin wirespec example=GraphQLExamples.kt#path
```

:::note
Nullable variables are sent as `null`, and GraphQL only falls back to the default of an argument when its variable is
left out. Configure the serialization to leave out null values to use the defaults.
:::

## Limitations

- Subscriptions get no client, because they are not a single request and response.
- Arguments of nested fields are not passed: a field that requires one cannot be selected.
- A partial result cannot tell a field that was not selected from a field that is `null`: both read as empty.
- A typed call returns a union as the Wirespec union of its models, which the serialization has to read by
  `__typename`. A partial result has no such need: it is a single type with the fields of every member.
- Scala has no serialization in Wirespec, so a Scala client needs one of your own.
