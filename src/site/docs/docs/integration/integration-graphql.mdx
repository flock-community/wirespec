The `graphql` integration ships an [IR extension](../plugins/plugins.md#ir-extensions) that generates a typed GraphQL
client from the [rpcs](../language/rpc.mdx) of a contract. Together with the [GraphQL converter](../converters/graphql.md),
which turns every field of `Query` and `Mutation` into an rpc, it gives you a client for a GraphQL API from its schema.
It works for the **Java** and **Kotlin** targets.

## What it does

Every rpc marked `@GraphQLQuery` or `@GraphQLMutation`, the annotations the [GraphQL converter](../converters/graphql.md)
puts on the fields of `Query` and `Mutation`, becomes a GraphQL operation. Any other rpc gets no client: a subscription,
and an rpc without a GraphQL annotation, so a contract can mix GraphQL operations with rpcs served another way. For each
operation the extension adds, in the `graphql` package:

- `<Rpc>Client`, which implements the `Service` of the rpc. It posts the GraphQL document of the rpc to `/graphql` with
  the parameters as its variables, and reads the result from the response.
- `GraphQLClient`, which implements every `Service` at once by delegating to those clients.
- `GraphQLError`, the error of a GraphQL response, with its `message`, `locations`, `path` and `extensions`.

The document is written at build time, so the generated code needs no GraphQL library: it sends the request through the
same `Wirespec.Transportation` and `Wirespec.Serialization` as the endpoint clients. For example, this schema:

```graphql
type Todo {
  id: ID!
  title: String!
  owner: User!
}

type User {
  name: String!
}

type Query {
  todo(id: ID!): Todo
}
```

converts to an rpc `QueryTodo`, whose client sends

```graphql
query QueryTodo($id: ID!) { result: todo(id: $id) { id title owner { name } } }
```

and can be called like this:

<Tabs>
  <TabItem value="kotlin" label="Kotlin">
    ```kotlin
    val client = GraphQLClient(serialization, transportation)

    val todo: Todo? = client.queryTodo(ID("1"))
    ```
  </TabItem>
  <TabItem value="java" label="Java">
    ```java
    GraphQLClient client = new GraphQLClient(serialization, transportation);

    Optional<Todo> todo = client.queryTodo(new ID("1")).join();
    ```
  </TabItem>
</Tabs>

### The query

- Every parameter of the rpc is a variable, typed and defaulted as the argument of the field it is passed to.
- The field is aliased as `result`, so the client reads it under the same name whatever the field is called.
- The query selects every field of the result, all the way down. A union or interface selects `__typename` and an
  inline fragment for each member, so the serialization can tell the members apart by `__typename`.
- GraphQL selects a finite set of fields, so a field that refers back to a type it is selected in, such as
  `User.todos` inside `Todo.owner`, or a field that takes a required argument, cannot be selected. Such a field is left
  out when it is nullable. When it is not, the build fails with a message that names the field.

### The response

A GraphQL response carries errors next to its data:

- An rpc without an error type throws an `IllegalStateException` that lists the `GraphQLError`s.
- An rpc with an error type, such as `rpc CompleteTodo { id: ID } -> Todo ! TodoError`, returns the first error, read
  as that type, as its `Error`, and the result as its `Result`.
- A required result that the response leaves out throws an `IllegalStateException`; a nullable one is `null` (or
  `Optional.empty()` in Java).

The response holds fields that the models do not have, such as `__typename` and the `locations` of an error, so
configure the serialization to ignore unknown properties. With Jackson:

```kotlin
val serialization = WirespecSerialization(
    ObjectMapper().configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false)
)
```

The request goes to the path `/graphql` of the transportation. To call a GraphQL API at another path, rewrite the path in
the transportation:

```kotlin
val transportation = Wirespec.Transportation { request -> http.transport(request.copy(path = listOf("api", "graphql"))) }
```

:::note
Nullable variables are sent as `null`, and GraphQL only falls back to the default of an argument when its variable is
left out. Configure the serialization to leave out null values to use the defaults.
:::

## Query builder

The clients select every field of a result. To pick the fields yourself, the extension also generates a query
builder: `GraphQLRequests` has a function per rpc that takes its parameters and a block that selects the fields of its
result. In the block you call the fields on `this`, a field of a type opens a block of its own, and a union has an
`on<Member>` block per member. It returns the `GraphQLRequest` of that rpc: the `query` and its typed `variables`.

<Tabs>
  <TabItem value="kotlin" label="Kotlin">
    ```kotlin
    val request = GraphQLRequests.queryTodo(ID("1")) {
        id()
        title()
        owner {
            name()
        }
    }

    request.query
    // query QueryTodo($id: ID!) { result: todo(id: $id) { id title owner { name } } }

    val search = GraphQLRequests.search("milk") {
        onTodo { title() }
        onUser { name() }
    }
    ```

    The selections carry a `@DslMarker`, so a block only reaches its own fields: `owner { title() }` does not compile.
  </TabItem>
  <TabItem value="java" label="Java">
    ```java
    var request = GraphQLRequests.queryTodo(new ID("1"), todo -> todo
        .id()
        .title()
        .owner(owner -> owner.name()));

    request.query();
    // query QueryTodo($id: ID!) { result: todo(id: $id) { id title owner { name } } }
    ```

    Every field returns the selection, so the fields chain in the lambda.
  </TabItem>
</Tabs>

The builder is written with the IR DSL and only uses the standard library, so the generated code stays
dependency-free.

### Partial results

A response to a selection only holds the fields you selected, so it cannot be read into the models, whose fields are
required. Every type and union that a query or mutation returns therefore also gets a `<Type>Result`: the same fields,
all nullable, with a field of a type or union read as its own result. A union result has `__typename` and the fields of
all its members; a field that members declare with different types is left out, because GraphQL cannot select it in
both.

The clients take a selection too. Next to `queryTodo(id)`, which returns the full `Todo`, there is `queryTodo(id) { ... }`,
which sends the request that the builder writes and returns a `TodoResult`. The fields you selected are filled, the
others are `null` (or `Optional.empty()` in Java):

<Tabs>
  <TabItem value="kotlin" label="Kotlin">
    ```kotlin
    val todo: TodoResult? = client.queryTodo(ID("1")) {
        title()
        owner { name() }
    }

    todo?.title       // "Groceries"
    todo?.owner?.name // "Ann"
    todo?.done        // null, not selected

    val results: List<SearchResultResult> = client.search("milk") {
        onTodo { title() }
        onUser { name() }
    }
    results.map { it.__typename } // ["Todo", "User"]
    ```
  </TabItem>
  <TabItem value="java" label="Java">
    ```java
    Optional<TodoResult> todo = client.queryTodo(new ID("1"), t -> t
        .title()
        .owner(owner -> owner.name())).join();

    todo.flatMap(TodoResult::title); // Optional["Groceries"]
    ```
  </TabItem>
</Tabs>

A call with a selection fails with an `IllegalStateException` on GraphQL errors, also for an rpc with an error type:
its `Result` and `Error` hold the full models.

## Setup

The extension is bundled with every Wirespec plugin as `GraphQLClient`. Register it with `extensionClasses`, by name in
Maven and by class in Gradle. Convert the schema to Wirespec first, or write the rpcs yourself.

<Tabs>
  <TabItem value="gradle" label="Gradle">
    ```gradle title="build.gradle.kts"
    import community.flock.wirespec.integration.graphql.extension.GraphQLClientExtension
    import community.flock.wirespec.plugin.gradle.CompileWirespecTask
    import community.flock.wirespec.plugin.Language

    tasks.register<CompileWirespecTask>("wirespec-compile") {
        input = layout.projectDirectory.dir("src/main/wirespec")
        output = layout.buildDirectory.dir("generated")
        packageName = "community.flock.wirespec.generated"
        // Works for Java and Kotlin
        language = Language.Kotlin
        extensionClasses = listOf(GraphQLClientExtension::class.java)
    }
    ```
  </TabItem>
  <TabItem value="maven" label="Maven">
    ```xml title="pom.xml"
    <plugin>
        <groupId>community.flock.wirespec.plugin.maven</groupId>
        <artifactId>wirespec-maven-plugin</artifactId>
        <version>{{WIRESPEC_VERSION}}</version>
        <executions>
            <execution>
                <id>generate</id>
                <goals>
                    <goal>compile</goal>
                </goals>
                <configuration>
                    <input>${project.basedir}/src/main/wirespec</input>
                    <output>${project.build.directory}/generated-sources</output>
                    <!-- Works for Java and Kotlin -->
                    <language>Kotlin</language>
                    <extensionClasses>
                        <extensionClass>GraphQLClient</extensionClass>
                    </extensionClasses>
                </configuration>
            </execution>
        </executions>
    </plugin>
    ```
  </TabItem>
  <TabItem value="cli" label="CLI">
    ```shell
    # Converts the schema and generates the client in one go
    wirespec convert -i ./schema.graphql -o ./build/generated -l Kotlin -e GraphQLClient GraphQL
    ```
  </TabItem>
</Tabs>

## Limitations

- Subscriptions get no client, because they are not a single request and response.
- An rpc you write yourself needs `@GraphQLQuery` or `@GraphQLMutation` to get a client. Mark it with `@GraphQLName`
  when the field it calls is not named after the rpc, such as `@GraphQLName("todo")` on `rpc QueryTodo`.
- Arguments of nested fields are not passed: a field that requires one is left out or fails the build, as described
  in [The query](#the-query).
- A [partial result](#partial-results) cannot tell a field that was not selected from a field that is `null`: both
  read as `null`.
