# Wirespec - Claude Code Instructions

## Generated Code Requirements

All code generated by Wirespec emitters must be **dependency-free**: fully self-contained, runnable with only the target language's standard library.

## Kotlin Code Style

Write idiomatic Kotlin, always.

- **Prefer expressions over statements**: expression bodies (`fun x(): T = ...`), `when`/`if` as expressions, single-expression chains. Explicit API mode is on, so anything effectively public needs its return type spelled out.
- **Chain calls where possible**: `map`/`filter`/`flatMap`/`fold` pipelines instead of intermediate variables and mutable accumulation.
- **Use scope functions**: `let`, `run`, `apply`, `also`, `with` — pick the right one for the job (`apply` for configuration, `let` for null-safe transforms, `also` for side effects).
- **Null handling**: `?.let`/`takeIf`/`?:` chains; never `?: return null` — prefer expression-style nullable chains.
- **Immutability first**: `val` over `var`, `List` over `MutableList`, data classes, sealed hierarchies.
- **Narrowest visibility that works**: `private` if it is only used in its own file, `internal` if only
  inside its own module, `public` only when another module or a consumer needs it. Never add `public`
  just to silence the compiler — check who actually calls it first.
- **Exhaustive `when`** over sealed types; no `else` branch that hides missing cases.
- **Extension functions** for behavior on types you don't own; keep them small and composable.
- **Be sparing with comments**: no narration, no KDoc that restates the signature. Comment only constraints the code can't express.
- **Match surrounding code**: naming, idiom, and structure of the file you're editing win over personal preference.

## Build & Test

Kotlin Multiplatform project built with Gradle.

Explicit API mode (`-Xexplicit-api=strict`) is enabled for every Kotlin module from the
root `build.gradle.kts`. It applies to `main` compilations and the common-metadata
compilation only — test and `codegen` compilations are unaffected. Two consequences when
adding code: every effectively-public declaration needs an explicit visibility modifier,
and every effectively-public function or property needs an explicit return type.

Some declarations must stay `public` even though nothing in this repo references them,
because a framework resolves them by name: the Maven `@Mojo` classes, the Gradle plugin
and task types, the FQCNs in the IntelliJ plugin's `plugin.xml`, Spring `@Configuration`
classes and `@Enable*` annotations, Jackson modules, `@JsExport` declarations, and the
kotest DSL entry points that `KotestDslExtension` writes into generated imports.

```shell
./gradlew build                                      # full build + all tests
./gradlew :src:compiler:emitters:kotlin:jvmTest      # JVM-only tests, quick feedback
./gradlew :src:compiler:emitters:kotlin:allTests     # all targets for one module
```

Scope tasks to the module you're working on (`:src:compiler:core`, `:src:compiler:ir`, `:src:compiler:emitters:{lang}`, ...) — a full multiplatform build is slow. Integration modules (`jackson`, `wiremock`, `spring`) generate their test sources into `build/generated/sources/wirespec` via a `generateWirespecTestSources` task backed by a private `codegen` compilation; nothing generated is checked in.

## Emitter Test Fixtures

Expected-output fixtures live in `src/compiler/emitters/{lang}/fixtures/{testName}.txt`; tests assert against the generated `EmitterFixtures.<testName>`.

Regenerate after intentional output changes (substitute the language):

```shell
./gradlew :src:compiler:emitters:kotlin:updateEmitterFixtures
```

Review the fixture diff before committing.
